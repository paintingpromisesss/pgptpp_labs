\section{Условие}
Цель работы: реализовать классификацию изображения на GPU с использованием константной памяти и одномерной сетки потоков, сравнить время вычислений на CPU и GPU.

\subsection*{Вариант 3. Метод минимального расстояния}
Для каждого класса задаётся выборка пикселей. Необходимо вычислить средний цвет класса и отнести каждый пиксель к классу с ближайшим средним цветом в пространстве RGB. При равенстве расстояний выбирается класс с меньшим номером.

Входные данные состоят из путей к исходному и выходному файлам, числа классов $n_c$ и описания каждого класса: числа пикселей выборки и их координат $(x,y)$. Ограничения: $n_c \leq 32$, размер выборки класса $n_p \leq 2^{19}$, $w h \leq 4\cdot10^8$. В начале файла изображения записаны два четырёхбайтовых целых числа $w,h$, за ними построчно следуют пиксели RGBA по четыре байта. Программа сохраняет цветовые компоненты и записывает в альфа-канал номер класса, начиная с нуля.

\section{Метод решения}
Для класса $j$ вычисляется средний цвет $\boldsymbol{\mu}_j=(\mu_{jr},\mu_{jg},\mu_{jb})$ по заданным пикселям. Класс пикселя $\boldsymbol{p}=(r,g,b)$ определяется выражением
\[
j^* = \operatorname*{arg\,min}_{j}\left[(r-\mu_{jr})^2+(g-\mu_{jg})^2+(b-\mu_{jb})^2\right].
\]
Для выбора ближайшего класса достаточно сравнить квадраты расстояний. Если расстояния равны, выбирается класс с меньшим номером.

Чтобы исключить ошибку округления при равенстве дробных средних, программа сохраняет для каждого класса суммы каналов $S_r,S_g,S_b$ и число пикселей $n$. Квадрат расстояния равен
\[
D = \frac{(rn-S_r)^2+(gn-S_g)^2+(bn-S_b)^2}{n^2}.
\]
Программа сравнивает дроби перекрёстным умножением. Для вычисления старшей части произведения в CUDA используется \texttt{\_\_umul64hi}. Это позволяет точно сравнить расстояния при заданных ограничениях.

CPU вычисляет суммы выборок, после чего программа копирует их в константную память GPU. Одномерная сетка имеет фиксированное число потоков. Каждый поток обрабатывает пиксели с шагом, равным числу потоков в сетке. Обозначим через $N=wh$ число пикселей изображения, а через $S$ общее число пикселей во всех выборках. Сложность алгоритма составляет $O(S+Nn_c)$ по времени и $O(N+n_c)$ по памяти.

\section{Описание программы}
В файле \texttt{main.cu} находятся функции чтения и записи изображения, код вычисления сумм на CPU и CUDA-функция \texttt{classify}. \section{Результаты}
На бинарных изображениях \texttt{04.data} и \texttt{09.data} проверены оба примера варианта 3 из методички. Номера классов совпали с ответами, каналы RGB сохранились. Дополнительно проверены случайные данные для 32 классов, обработка неверных координат и выбор меньшего номера при равных расстояниях, в том числе для дробных средних.

Для замеров использованы синтетические изображения из четырёх повторяющихся цветов. Их размеры: $500\times200$, $2500\times2000$ и $20000\times20000$ пикселей. В каждом случае заданы четыре класса с одним пикселем в выборке. Последнее изображение достигает ограничения $4\cdot10^8$ пикселей. CPU-версия собрана с \texttt{g++ -O3} и работает в одном потоке. В таблице указано время классификации на CPU и время выполнения CUDA-функции на GPU, измеренное с помощью CUDA Events. В обоих случаях замер не включает чтение файлов и вычисление сумм выборок; для GPU также не учитывается передача данных. Каждая конфигурация запускалась один раз. Время указано в миллисекундах.

\section{Выводы}
Метод минимального расстояния классифицирует пиксели по цвету. Его можно применять для выделения областей изображения, в том числе на спутниковых снимках, и для предварительной обработки изображений в задачах компьютерного зрения.

Основная трудность реализации заключалась в сравнении расстояний при дробных средних: округление могло нарушить правило выбора класса с меньшим номером. Проблему решило целочисленное сравнение дробей. Параметры классов хранятся в константной памяти; пиксели обрабатывает одномерная сетка потоков.

На изображении из $400\,000\,000$ пикселей при конфигурации $(1024,256)$ CPU затратил 4396{,}900 мс, GPU затратил 16{,}383 мс. На $5\,000\,000$ пикселей время GPU при конфигурации $(1,32)$ составило 91{,}813 мс, при $(1024,1024)$ оно составило 0{,}166 мс. Во втором случае работу можно распределить между большим числом потоков. Влияние конфигурации зависит от размера изображения и накладных расходов запуска. Каждый результат получен за один запуск, а передача изображения на GPU не учитывается, поэтому определить полное ускорение программы по этим числам нельзя.
