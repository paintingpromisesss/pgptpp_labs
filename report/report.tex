\section{Условие}
\subsection*{Цель работы и общая постановка задачи}
Целью лабораторной работы является освоение обработки изображений на GPU с использованием текстурной памяти и двухмерной сетки потоков, а также практическая реализация фильтра изображения с оценкой достигнутого ускорения относительно CPU.

\subsection*{Вариант задания}
\textbf{Вариант 1. Гауссово размытие.}
Необходимо реализовать размытие по Гауссу с линейной сложностью от радиуса размытия (двухпроходный алгоритм).
\begin{itemize}
    \item \textbf{Входные данные:} на первой строке задается путь к исходному изображению, на второй --- путь к конечному изображению. На следующей строке задано целое число $r$ --- радиус размытия ($w \cdot h \le 5 \cdot 10^{7}$, $0 \le r < 1024$).
    \item \textbf{Выходные данные:} обработанное изображение, записанное в тот же бинарный формат: первые восемь байт --- размеры $w$ и $h$ (тип \texttt{int}), далее построчно значения пикселей $r$, $g$, $b$, $a$ (по 4 байта на пиксель).
    \item \textbf{Ограничения:} используются только цветовые составляющие ($r$, $g$, $b$), альфа-канал не учитывается; допускается ошибка в $\pm 1$. В пограничном случае изображение ``расширяется'' за границы дублированием граничных пикселей: $ip := \max(\min(i, h), 1)$, $jp := \max(\min(j, w), 1)$.
\end{itemize}

\section{Метод решения}
\subsection*{Формат изображения и идиома Threaded 2D}
Изображение хранится в бинарном формате: $w$, $h$ (4-байтовые целые), далее построчно пиксели \texttt{uchar4} $(r, g, b, a)$. Каждому пикселю сопоставляется своя нить GPU: идея \textbf{двухмерной сетки потоков} --- глобальные индексы нити вычисляются как
\begin{lstlisting}[language=C++]
int idx = blockIdx.x * blockDim.x + threadIdx.x; // x (column)
int idy = blockIdx.y * blockDim.y + threadIdx.y; // y (row)
\end{lstlisting}
Для обработки произвольных размеров при фиксированной сетке применяется двухмерный grid-stride цикл: нить стартует со своего глобального индекса $(idx, idy)$ и сдвигается с шагом $(\text{blockDim.x} \cdot \text{gridDim.x},\ \text{blockDim.y} \cdot \text{gridDim.y})$ по обеим осям.

\subsection*{Двухпроходный алгоритм (сепарабельность ядра)}
Двумерная гауссова свертка вычисляется по формуле
\[
G'(i, j) = \sum_{k = -r}^{r} \sum_{m = -r}^{r} w(k)\, w(m)\, G(i + k, j + m), \qquad w(k) = \frac{e^{-k^{2} / (2 r^{2})}}{\sum_{t = -r}^{r} e^{-t^{2} / (2 r^{2})}},
\]
где $G$ --- исходная яркость пикселя. Поскольку ядро $W(k, m) = w(k)\, w(m)$ сепарабельно, свертка раскладывается на два одномерных прохода:
\begin{enumerate}
    \item \textbf{Горизонтальный проход:} $T(i, j) = \sum_{k} w(k) G(i, j + k)$ (радиус $r$);
    \item \textbf{Вертикальный проход:} $G'(i, j) = \sum_{k} w(k) T(i + k, j)$ (радиус $r$).
\end{enumerate}
Сложность алгоритма составляет $O(w \cdot h \cdot r)$ вместо $O(w \cdot h \cdot r^{2})$ для наивной двумерной свертки; при $r = 100$ это сокращение числа умножений в $100$ раз ($402$ операций против $40401$ на пиксель).

\subsection*{Текстурная память}
Промежуточные чтения соседних пикселей выполняются через текстурную память (\texttt{cudaTextureObject\_t} поверх 2D-массива \texttt{cudaArray}):
\begin{itemize}
    \item \textbf{режим адресации \texttt{cudaAddressModeClamp}} аппаратно реализует требуемое методомичкой правило «расширения» изображения за границы: при выходе индекса за $[0, w) \times [0, h)$ возвращается граничный пиксель ($ip := \max(\min(i, h), 1)$), что исключает ветвления в ядрах;
    \item \textbf{точечная фильтрация (\texttt{cudaFilterModePoint})} и ненормированные координаты обеспечивают точное чтение пикселя по координатам $(j + 0{,}5;\; i + 0{,}5)$;
    \item текстурный кэш локализует чтения: в каждом проходе пиксель читается $(2r + 1)$ раз, и обращения соседних нитей многократно попадают в кэш.
\end{itemize}
Исходное изображение загружается в текстуру \texttt{uchar4} один раз на этапе чтения; результат горизонтального прохода (\texttt{float4}, во избежание накопления погрешностей округления) копируется во вторую текстуру перед вертикальным проходом.

\section{Описание программы}
Программа декомпозирована на исходный модуль на языке CUDA C++ (\texttt{main.cu}), CPU-референс для верификации (\texttt{report/cpu\_ref.cpp}) и сборочный конфигурационный файл (\texttt{Makefile}).

\subsection*{Основные типы данных и функции}
\begin{itemize}
    \item \textbf{Типы данных:}
    \begin{itemize}
        \item \texttt{uchar4} --- пиксель изображения (8-битные каналы $r, g, b, a$);
        \item \texttt{float4} --- промежуточное представление канала $r, g, b$ с плавающей точкой (\texttt{float}), \(a\) не учитывается;
        \item \texttt{cudaTextureObject\_t}, \texttt{cudaArray\_t}, \texttt{cudaChannelFormatDesc} --- для работы с текстурной памятью;
        \item \texttt{dim3} --- конфигурация сетки и блока потоков.
    \end{itemize}
    \item \textbf{Макрос \texttt{CSC}:} перехватывает ошибки функций CUDA API, печатает сообщение в поток \texttt{stderr} с указанием файла, строки и описания через \texttt{cudaGetErrorString}, после чего завершает работу программы.
    \item \textbf{Ядро \texttt{gauss\_horizontal}:} \texttt{\_\_global\_\_}-функция, горизонтальный проход гауссовой свертки; чтение пикселей через текстурный объект \texttt{uchar4} в режиме Clamp, запись результата (каждому пикселю своя нить, 2D grid-stride) в массив \texttt{float4};
    \item \textbf{Ядро \texttt{gauss\_vertical}:} \texttt{\_\_global\_\_}-функция, вертикальный проход; чтение промежуточного представления через текстурный объект \texttt{float4} в режиме Clamp, запись финального изображения в \texttt{uchar4} с ограничением значений отрезком $[0, 255]$ и обнуленным альфа-каналом;
    \item \textbf{Функции \texttt{make\_object\_uchar4}, \texttt{make\_object\_float4}:} создают 2D-текстурный объект (\texttt{cudaMallocArray} + \texttt{cudaCreateTextureObject}) с режимом адресации \texttt{cudaAddressModeClamp}, точечной фильтрацией и ненормированными координатами;
    \item \textbf{Функции \texttt{read\_image}, \texttt{write\_image}:} бинарный ввод/вывод изображения в формате ЛР;
    \item \textbf{Функция \texttt{main}:} читает пути к файлам и радиус $r$, строит нормализованное ядро $w(k)$ и загружает его в глобальную память GPU, загружает изображение, запускает два ядра, синхронизирует GPU (\texttt{cudaEventSynchronize}), копирует результат на хост и записывает выходной файл; замер времени производится средствами CUDA Events.
\end{itemize}

\section{Выводы}
\subsection*{Область применения алгоритма и типовые задачи}
Гауссово размытие --- базовая операция обработки изображений, лежащая в основе множества прикладных алгоритмов:
\begin{itemize}
    \item построение пирамид изображений (mipmap) и высококачественное уменьшение разрешения с предварительной низкочастотной фильтрацией (антиалиасинг);
    \item компьютерное зрение: сглаживание шума перед детекторами границ (Canny), построение пирамид разности гауссианов (DoG) для локализации ключевых точек (SIFT);
    \item графика реального времени: постэффект bloom/glow, объемное освещение (light shafts), эффекты дымки и боке (depth of field);
    \item научные вычисления: ядро сглаживания в симуляциях частиц (SPH), размытие карт плотностей (kernel density estimation).
\end{itemize}

\subsection*{Оценка сложности программирования и возникшие проблемы}
\begin{itemize}
    \item \textbf{Сложность программирования:} алгоритмическая сложность по времени $O(w \cdot h \cdot r)$ (двухпроходная сепарабельная схема), по дополнительной памяти $O(w \cdot h)$ на GPU (промежуточный массив \texttt{float4} и текстуры). Двухмерная сетка нитей в сочетании с текстурной памятью в режиме Clamp позволяет переложить граничную логику на аппаратуру и делает ядро компактным.
    \item \textbf{Возникшие проблемы:}
    \begin{enumerate}
        \item текстурный объект поверх линейной памяти (\texttt{cudaResourceTypeLinear}) является одномерным и не поддерживает 2D-индексацию с зажимом по обеим осям --- потребовался переход на \texttt{cudaResourceTypeArray} с копированием через \texttt{cudaMemcpy2DToArray};
        \item точность: при $r = 100$ ($201$ тап на проход) промежуточные значения необходимо хранить в вещественном виде, поэтому проходы связаны через буфер \texttt{float4}, а финальный клампинг значений выполняется в диапазоне $[0, 255]$
    \end{enumerate}
\end{itemize}

\subsection*{Сравнение и объяснение полученных результатов}
Эксперименты показали, что:
\begin{enumerate}
    \item На предельном изображении ($N = 20\,000\,000$ пикселей, $r = 100$) ядро GPU обгоняет однопоточный CPU более чем в $500$ раз ($33.8$ мс против $17\,178.3$ мс), а полная обработка (включая передачу данных по PCI-Express и текстурные копирования) --- более чем в $205$ раз.
    \item Лучшие конфигурации достигаются при заполнении всех $48$ мультипроцессоров ($\ll 256, 256 \gg$, $\ll 32, 256 \gg$): время ядра $33.82$ мс против $152.02$ мс у конфигурации $\ll 1, 32 \gg$ (ускорение в $4.5$ раза при том же алгоритме).
    \item Чрезмерно большие сетки ($\ll 1024, 1024 \gg > 1$ млн нитей) на малых изображениях дают обратный эффект из-за накладных расходов на диспетчеризацию избыточных нитей.
\end{enumerate}
